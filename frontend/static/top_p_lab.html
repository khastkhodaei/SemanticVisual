SIMULATOR SCOPE

Simulator Scope & Implementation Boundaries

Clarifying what is modeled in this interactive demonstration vs. the complete production protocol.

📚Pedagogical Storyboard vs. Deep Learning Paper Regime Simulator
1. Weight Distributions & Model Dimension: In the 10-node CIFAR-10 storyboard (Steps 1–34), clients hold normalized 10-dimensional class distribution vectors where $P = 3$ ($30\%$ of dimension) with $\theta = 0.70$ is chosen for intuitive visualization and manual verification.
In the Deep-Dive Lab and the real paper regime, models contain $M = 10^6$–$10^8$ weights (e.g. ResNet-18 with $M = 11.7\text{M}$) where $P \approx 10\%–13\%$ achieves $\cos \ge 0.80$.
2. Synthetic Heavy-Tailed Sampling in the Lab: The Top-P Extraction simulation tab synthesizes heavy-tailed weights with latent cluster seeds ($W = \text{bases}[c] + 0.35 \cdot \text{noise}$) to reproduce realistic parameter spectra without requiring local GPU training.
3. Distributed Topology & VRF Integration: The complete multi-phase pipeline (VRF leader election, TTL-bounded zone flooding, inter-zone boundary notifications, and Affinity Propagation meta-clustering) is executed step-by-step in the main application storyboard (Steps 3 through 19).
4. Out-of-Scope Behaviors: As defined in the paper [§2.4, §2.5], dynamic node churn and Byzantine adversarial data poisoning are handled via cryptographic VRF seeds and $(1-q)$ quantile bounds; active malicious packet manipulation is excluded from the normal execution simulator.

Step 3 — Directional Cosine Calculation cos(P)

Simulator

The directional cosine similarity $\cos(w, w^{[P]})$ retained by keeping the top $P$ coordinates is $\sqrt{c_P} / \|w\|_2$:

$$\cos(P) = \frac{\sqrt{c_P}}{\|w\|_2} = \frac{\sqrt{c_P}}{\sqrt{17.16}}, \qquad \text{e.g., at } P=3: \; \cos(3) = \frac{\sqrt{15.25}}{\sqrt{17.16}} = \frac{3.9051}{4.1425} = 0.943$$

Step 4 — Feasibility Test against Target θ = 0.9

Simulator

To satisfy $\cos(w, w^{[P]}) \ge \theta$, we test the algebraic condition $c_P \ge \theta^2 \|w\|_2^2$:

$$c_P \ge \theta^2 \|w\|_2^2 = (0.90)^2 \times 17.16 = 0.81 \times 17.16 = 13.90$$
For P = 2: $c_2 = 13.00 < 13.90$ (fails, $\cos(2) = 0.870 < 0.90$)
For P = 3: $c_3 = 15.25 \ge 13.90$ (passes, $\cos(3) = 0.943 \ge 0.90$) $\to P_{\min} = 3$

💡 Note: with $\theta = 0.8$ the answer would be 2 (since $\theta^2 \|w\|^2 = 0.64 \times 17.16 = 10.98$ and $c_2 = 13.00 \ge 10.98$).

Step 6 — Super-Peer Shared P Consensus (q = 0.8)

Simulator

When five clients in a zone report their minimal budgets $P_{\min} = [3, 2, 4, 3, 6]$, the Super-Peer sets global shared $P$ using quantile $q = 0.8$:

$$\text{sorted } P_{\min} = [2, 3, 3, 4, 6], \qquad k = \lceil q \cdot n \rceil = \lceil 0.8 \times 5 \rceil = 4 \implies P_{\text{global}} = 4$$
4 of 5 clients (80%) satisfy $\theta = 0.9$:
Clients requiring $P_{\min} \in \{2, 3, 4\}$ receive a signature with $P=4 \ge P_{\min}$, exceeding their target fidelity $\theta = 0.90$.
1 client requiring $P_{\min} = 6$:
Achieves $\cos(4) = 0.973$ (slightly below its personal $\theta$ demand, bounded by $(1-q)$ consensus to prevent outlier bloat).

Step 7 — Signature Wire Sizing Cost & Paper Scale

Simulator Derived

Each signature entry encodes a 4-byte coordinate index and a 2-byte FP16 parameter value:

$$\text{Payload} = P \times (b_{\text{idx}} + b_{\text{val}}) = 4 \times (4\text{ B} + 2\text{ B}) = 24\text{ bytes vs dense } 10 \times 4\text{ B} = 40\text{ bytes}$$
Paper-Scale Deep Learning Regime (ResNet-18):
• Parameter dimension: $M = 11.7\text{M}$ coordinates (FP32 dense model $\approx 46.8\text{ MB} \approx 47\text{ MB}$)
• Top-$P$ signature budget: $P = 10.8\% \times 11.7\text{M} \approx 1.26\text{M}$ entries
• Wire signature size: $1.26\text{M} \times 6\text{ bytes} \approx 7.23\text{ MB}$ Derived
• Compression saving: $6.5\times$ payload reduction ($47\text{ MB} \to 7.23\text{ MB}$) while preserving $\cos \ge 0.80$ directional accuracy.
