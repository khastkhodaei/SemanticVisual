⚡Step 1: Multi-Round Importance Scores & Coordinate Ranking (EMA Smoothing)
⚡ Cached (β=0.9) Multi-Round EMA
📐Mathematical Formulation: Multi-Round Exponential Moving Average (EMA)

In decentralized federated topologies, transient noise from local client stochastic gradient steps can destabilize single-round coordinate rankings. The multi-round importance score $s_{i,r}^{(t)}$ smooths coordinate salience across rounds:

$$s_{i,r}^{(t)} = \beta \cdot s_{i,r}^{(t-1)} + (1 - \beta) \cdot |w_{i,r}^{(t)}| \quad \text{with } s_{i,r}^{(1)} = |w_{i,r}^{(1)}|$$
Smoothing Factor $\beta \in [0.0, 0.99]$: Balances historical memory retention against latest round magnitude adaptation. Coordinates with identical scores are sorted with deterministic index tie-breaking to guarantee absolute consensus across all distributed nodes.
ℹ️ Precision Note: All EMA evaluations, tensor calculations, and ranking argsorts are performed with full floating-point precision (FP32/FP64). Values in this table are formatted to 6 decimal places strictly for visual clarity.
⏱️Sorting Complexity & Amortization Analysis (Appendix B, Page 29)
Time Complexity: $\mathcal{O}(M \log M)$ per full sorting pass over $M$ parameters.
Memory Complexity: $\mathcal{O}(M)$ auxiliary storage for coordinate permutation vector $J$.

Amortization Across Rounds ($T_{\text{ref}}$): Because coordinate salience distributions evolve smoothly under decentralized momentum, coordinate importance orders shift slowly. Sorting can be amortized by re-ranking only once every $T_{\text{ref}} > 1$ communication rounds, reducing empirical sorting computational overhead to near zero.

⚡Step 2: Energy Distribution & Cumulative Prefix Sums — $c_P$ Paper §3.2 & App. B
📐 Mathematical Foundation: Energy Concentration & $\mathcal{O}(1)$ Directional Cosine Theorem / Equation (3)

In Top-$P$ coordinate selection, coordinates are sorted descending by importance $s^{(t)}$ into permutation vector $J$. The accumulated squared energy $c_P$ and total energy $\nu^2$ are defined as:

$$\cos\left(w, w^{[P]}\right) = \frac{\langle w, w^{[P]} \rangle}{\|w\|_2 \|w^{[P]}\|_2} = \frac{\sqrt{c_P}}{\nu} \quad \text{where } c_P = \sum_{m=1}^P (w_{J_m})^2 \text{ and } \nu^2 = \|w\|_2^2$$

Because coordinates are orthogonal, $\langle w, w^{[P]} \rangle = \|w^{[P]}\|_2^2 = c_P$. Once the 1D prefix sum array $c_P$ is evaluated in a single pass ($\mathcal{O}(M)$), computing the directional cosine similarity $\cos(w, w^{[P]})$ for any budget $P$ costs strictly $\mathcal{O}(1)$ time with zero inner products needed.

💡 Invariant: Since $(w_{J_m})^2 \ge 0$, both $c_P$ and $\cos(P)$ are strictly non-decreasing with $P$. At full budget $P = M$, $c_M = \nu^2$ and $\cos(M) = 1.000000$ identically.

⚡Step 3: Minimal Signature Budget Search — $P_{\min}$ (Algorithm 1 Trace) Paper §3.2 & App. B
📐 Mathematical Foundation: Exact Binary Search for $P_{\min}$ Algorithm 1 (Page 29)

Given a target directional cosine threshold $\theta \in (0, 1]$, each client seeks the minimum coordinate budget $P_{\min}$ such that the sparsified model achieves at least $\theta$ directional fidelity with the original model:

$$\text{Find } \min P \in [1, M] \quad \text{s.t.} \quad \cos\left(w, w^{[P]}\right) \ge \theta \iff c_P \ge \theta^2 \cdot \nu^2$$

Because coordinates are sorted descending by importance, the prefix sum array $c_P$ is monotonically non-decreasing. This monotonicity strictly guarantees that binary search locates the global minimum budget $P_{\min}$ in exactly $\lceil \log_2 M \rceil \approx 22$ checks (out of $2,156,490$ parameters) without exhaustive scanning!

ℹ️ Logarithmic Convergence: At each iteration step $k$, feasibility is evaluated in $\mathcal{O}(1)$ time against precomputed energy $c_{\text{mid}}$. The search interval is halved at every check ($[lo .. hi] \to \text{half}$), converging exponentially to optimal $P_{\min}$.

🔄S1 to S9 — Stage-by-Stage Protocol Mechanics & Exact Cost Accounting Paper §3.2–§3.7, App. B & D

The SemanticDFL decentralized protocol organizes client peer discovery into 10 structured phases matching the storyboard simulator:

S1. VRF Initiator Election (Steps 1–4) §3.3.1

Each peer computes one verifiable random function score $\sigma_p = \text{VRF}_p(\text{seed})$. Nodes exchange $(\sigma, \text{id})$ within $R$-hop radius ($\approx |N_R(p)|$ small headers). Node state is $O(1)$ memory; executed once per overlay epoch (not per round).

S2. Proximity Zone Formation (Steps 5–6) §3.3.1, App. B.2

Initiators flood PROBE with $\text{TTL}=R$ (first-wins). Messages: $O(S_Z)$ per zone ($O(N)$ across network). Zone cap $S_Z = 0.05N$. Split rule: deterministically transfers excess peers if $|Z| > S_Z$. Initiator memory: $O(S_Z)$; ordinary peers: $O(1)$.

S3. $P$ Selection & Signatures (Steps 7–11) §3.2, App. B.1

Local binary search ($O(M \log M)$ sort + $O(M)$ prefix sums) finds minimal $P_{\min}$ satisfying $\cos(w, w_{[P]}) \ge \tau_{\min} (0.8)$. Zone aggregates $q$-quantile ($q \in [0.8, 0.9]$) to set global $P$. Pruning $84\%–93\%$ parameters retains $>80\%$ directional fidelity.

S4. Intra-Zone AP Clustering (Steps 12–13) §3.3.2

Initiator collects signatures ($O(n_z \cdot P)$ bytes), forms $n_z \times n_z$ similarity matrix ($O(n_z^2 P)$ ops), and executes Affinity Propagation without needing a pre-fixed cluster count $k$. Extracts cluster prototype $\bar{u}_j$ and descriptor $CD_j$. Replicates to $r=3$ super-peers.

S5. Inter-Zone Recursive SON Build (Steps 14–19) §3.3.3, Props 1–3

Recursive AP clustering on super-peer prototypes builds tree of depth $H = \lceil \log_{S_Z} N \rceil = O(\log N)$. Per-node control cost is $O(1)$; total network control traffic is $O(N)$ (Prop. 1). Build time is $O(\log N)$ (Prop. 2). Worst-case super-peer memory is $O((S_P+S_D)S_Z \log N)$ (Prop. 3).

S6. Maintenance & Fault Tolerance (Steps 20–21) §3.7

Short leases with deterministic successors $(\text{VRF}, \text{id})$. Super-peer replica set $r=3$ masks single-node failures immediately. Joins, graceful leaves, and dropouts trigger only local parent/child pointer patches—no global network coordination required.

S7. Similarity Search Per Round (Steps 22–29) §3.4, §3.5

Top-down beam search ($O(PFBH)$ comparisons, $O(BH)$ messages) with adaptive threshold $\tau^{(t)}$ controller. If distinct candidates $< K$, relaxes $\tau \leftarrow \tau - 0.02$. Only signatures travel during search ($109–133\text{ MB}$); achieves Recall@K $\ge 0.88–1.00$.

S8. Model Pull & Personalization (Steps 30–33) §2.1, §3.4, Tbl 11

Client pulls only $K=0.10N$ full models ($O(KM)$). Computes Softmax similarity weights $W_{ij} = \text{softmax}((s_{ij}-c_i)/\kappa)$ and regularized update $w_i \leftarrow (1-\alpha_i)\tilde{w}_i + \alpha_i m_i$ with optimal $\psi=2$ ($\alpha_i = \eta\psi/(1+\eta\psi)$).

🔍S13 & S14 — Scientific Audit, Caveats & Tab Corrections Paper §2.4, §2.5, §5.1
S13 — Methodological Caveats & Hidden Costs:
  1. Data plane scales linearly with $N$: Pulling $K = 0.10N$ full models means per-node pull data grows as $O(0.1NM)$. The $O(\log N)$ bound applies strictly to search and tree construction, not to model downloads.
  2. Signatures expose raw parameters: Signatures $u = \text{mask}(w, \text{Top-}P)$ reveal $\approx 10\%$ of actual weights. Differential privacy (DP) and Byzantine robustness are out of scope (honest clients assumed).
  3. Local AP Compute: Sorting $O(M \log M)$ and computing the $n_z \times n_z$ similarity matrix $O(n_z^2 P)$ is amortized but not quantified separately in Fig 5.
  4. Dual $P$ Values in Paper: Section 3.4 uses worked example values ($10.8\%$ and $13.3\%$) while Section 5.1 and App. E.1 use tuned optima ($9.6\%$ and $11.2\%$). Both are accurately presented here.
